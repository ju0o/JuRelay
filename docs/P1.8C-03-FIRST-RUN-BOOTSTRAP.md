**Status:** local implementation  
**Date:** 2026-10-07  
**Pre HEAD:** `8c9003f90610f4296981cd1e072889d12f61cffd`

## Goal

When the production MCP App widget opens with no suitable persisted project,
show a bounded bootstrap wizard:

Project 선택 → workspace 확인 → PM / Builder / QA → 준비 완료 → Dashboard

`준비 완료` / `BOOTSTRAP_READY` means **context is configured**. It does **not**
create Goals, Tasks, Runs, spawn workers, open tmux, or start shell/Git work.

## First-run vs returning

| Condition | UI |
|---|---|
| No `selectedProjectId`, missing profile, LEGACY, UNCONFIGURED, workspace missing/conflict | Bootstrap wizard |
| Valid CONFIGURED (or PARTIAL with real non-conflicting workspace) selection | Skip wizard; show `Project ▾` |

Storage scope `ws` alone never forces the wizard. Canonical `agent-relay` and
legacy `ws` stay separate profiles.

## Ownership

| Concern | Store / API |
|---|---|
| Project choice | C01 `relay_pm_select_project` → `_relay/ui-state.json` |
| Assignments | C02 get/set → RoleConfig or WorkspaceConfigV2 |
| Workspace path | Existing WorkspaceConfigV2 / RoleConfig only — never invented |
| Wizard step | Client/widget-local only |

No new wizard database. No new MCP tools unless a narrow workspace-config
write is later required; C03 surfaces `WORKSPACE_CONFIGURATION_REQUIRED`
instead of faking a path.

## Widget

- Single production resource: `ui://agent-relay/pm-widget-<8hex>` (content hash)
- Bootstrap overlay lives inside the existing shell (not a second debug widget)
- Reuses: `relay_pm_list_project_profiles`, `relay_pm_select_project`,
  `relay_pm_get_project_assignments`, `relay_pm_set_project_assignments`
