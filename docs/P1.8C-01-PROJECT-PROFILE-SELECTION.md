## Decision

`ProjectProfile` is a **derived view**, not a durable database.

Sources (existing only):

| Source | Path / module | Role |
|---|---|---|
| ProjectIdentity | `src/backend/project-identity.ts`, `_relay/projects.json` | canonical id/name |
| WorkspaceConfigV2 | `.agent-relay/workspace-config.json` | lane root + role bindings |
| RoleConfig | `_relay/roles/<project>.json` | role/runtime/workspaceRoot |
| WorkerRegistry | `_relay/workers/*.json` | **availability only** |
| Runtime truth | `src/backend/runtime-truth.ts` | optional summary |
| UI state (NEW) | `_relay/ui-state.json` | `selectedProjectId` only |

## Workspace path precedence

1. `WORKSPACE_CONFIG` — matching lane.root  
2. `ROLE_CONFIG` — RoleAssignment.workspace.workspaceRoot  
3. If both exist and resolve differently → `workspaceConflict: true`, `profileState: PARTIAL` (never silently pick)  
4. Host roots are discovered from RoleConfig workspace roots (bounded walk-up ≤3 for workspace.v2), optional caller `hostRoots`, and cwd when it already has workspace.v2. No home/disk scan.

## Selection

Precedence for dashboard/read APIs:

1. explicit `projectId` argument → `ARGUMENT`  
2. persisted `selectedProjectId` → `SELECTED`  
3. recent-active runtime → `LAST_ACTIVE`  
4. scope identity → `SCOPE`

`relay_pm_select_project` persists selection only. Zero Goals/Tasks/dispatches/workers/workspace/Git mutations.

Legacy `ws` remains a separate `LEGACY` profile and is never merged into canonical `agent-relay`.

## MCP

- `relay_pm_list_project_profiles`

- `relay_pm_select_project`

Dashboard additive keys: `projectProfiles`, `selectedProjectProfile`, `selectedProjectId` (plus extended `selectedProjectBasis`).

## Out of scope (C02+)

Role assignment editing, first-run wizard, widget redesign, Goal/Task auto-create, orphan resolution, historical `ws` migration.
