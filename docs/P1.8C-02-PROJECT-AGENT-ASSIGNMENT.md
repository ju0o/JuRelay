`workspace.v2` remains singular `builder`/`qa` for runners; optional additive
`builders[]` / `qas[]` hold multi-binding when length > 1 (`[0]` must match
the singular field). RoleConfig still allows at most one assignment per roleId.

### Optional explicit `workerId` (OWNER-02A)

`RoleBinding` may include optional `workerId` (WorkerRegistry id). Rules:

- runtime/model/`roleProfile` stay required; `workerId` is additive
- `toWorkspaceBinding()` persists `workerId` (no drop on write)
- ProjectProfile / get-assignments expose `workerId` when present
- `relay_pm_resolve_run` prefers explicit `workerId` over runtime/model scoring
- unknown registry id → `UNKNOWN_WORKER` (set) / resolve fail-closed
- equal-score runtime maps (e.g. two `builder-claude-*` for `claude`) →
  `BUILDER_AMBIGUOUS` — never pick arbitrarily
- bindings without `workerId` keep prior runtime-only behavior
